# DISCOVERY.md

新しい機能・プロダクト・大きな方向性を考えるときに使う。

Humanが提示した解決策をそのまま要件化せず、
まず実際の問題を最小単位まで分解する。


# 1. Problem

Humanが実際に困っていることを確認する。

- 何が起きたか
- どこが一番不便か
- 何を減らしたい / 楽にしたいか

機能名や技術名ではなく、具体的な困りごととして整理する。


# 2. Strip the Solution

Humanの発言に解決策が混ざっていないか確認する。

例：

「AI検索が欲しい」
→ AIは解決策かもしれない。

「良質な記事を簡単に見つけたい」
→ より根本のニーズ。

AI、自動化、新規アプリ、特定技術を前提にしない。


# 3. Minimize

今回解決する問題を、実用性を失わない最小単位まで縮める。

大きな問題全体を一度に解こうとしない。


# 4. Options

最小化した問題に対して複数の解決案を出す。

以下も候補に含める。

- 既存機能を使う
- 既製ツールを使う
- 運用方法を変える
- 小さな追加実装をする
- AIを使う
- 何もしない

必要以上に大きな解決策を優先しない。


# 5. Future Needs

今は実装しないが、将来的に必要になる可能性が見えたものは
現在の要件から分離する。

必要なら `IDEAS_AND_HYPOTHESES.md` に記録する。

将来ニーズは保存してよいが、
具体的な解決方法を将来仕様として固定しない。


# 6. Decide

今回実際に解決する最小の問題と、
採用する解決方針をHumanと確認する。

Humanが判断できるよう、
各案の違い・コスト・制約を非エンジニア向けに説明する。


# Output

完了時には最低限、以下が分かる状態にする。

- 今回解決する問題
- 今回は解決しないこと
- 採用する解決方針
- 将来へ分離したニーズ
