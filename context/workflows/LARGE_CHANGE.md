# LARGE_CHANGE.md

影響範囲の大きい変更を行うときに使う。

共通の実装工程（構造確認・検証計画・実装・検証）は
`IMPLEMENTATION.md` を参照する。このWorkflowでは工程を複製せず、
**大きな変更で追加する観点だけ**を扱う。

# 1. Impact & Rollback

通常変更より先に、以下を確認する。

- どこまで変わるか（機能・構造・影響を受ける部分）
- 変更しない部分はどこか
- **どう壊れるか・どう戻せるか**（ロールバック手段）
- 既存データや設定に影響するか

# 2. Split

可能なら変更を安全な単位へ分割し、途中で検証できる境界を作る。

大規模な未コミット変更が増えすぎる場合は、
安全な地点でHumanへコミットを提案する。

# 3. Verify (Broader than normal)

変更対象だけでなく影響を受ける周辺も含め、
通常変更より広い範囲の回帰確認を行う。

問題が見つかった場合は `BUG_FIX.md` を使う。

# Output

- 何を大きく変更したか
- どこまで影響したか
- どう検証したか
- 既存機能への影響を確認できたか
- 残っているリスクやHuman確認があるか
