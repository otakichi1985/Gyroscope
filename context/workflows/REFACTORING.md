# REFACTORING.md

現在の構造が、実際の変更・理解・検証を邪魔しているときに使う。
「綺麗にできる」だけを理由に実施しない。

# Triggers

以下が繰り返し起きる場合はリファクタリングを検討する。

- 小さな変更でも多数の箇所を触る
- 同じ修正を複数箇所へ入れる
- 同じ構造でバグやHuman介入が繰り返す
- 変更対象や責務の境界が分かりにくい
- 検証・観測が構造上やりにくい
- 大規模変更の前に現在構造が明確な障害になっている
- 大規模変更後に一時的な処理や重複が残っている

# 1. Identify

何が実際に変更コストを上げているか特定する。

# 2. Preserve Behavior

現在の正常動作と検証方法を確認する。
リファクタリングでは原則として外部挙動を変えない。

# 3. Reduce

問題になっている複雑さだけを小さくする。
周辺まで「ついでに綺麗にする」ことを避ける。

# 4. Verify

変更前と同じ挙動が維持されていることを確認する。

# Output

- 何が変更を邪魔していたか
- 何を単純化したか
- 挙動が維持されているか
