# BUG_FIX.md

不具合の調査・修正を行うときに使う。

原因を推測して変更を繰り返すのではなく、
再現・観測・切り分けを優先する。


# 1. Reproduce

まず不具合を再現する。

- 何をすると起きるか
- 何を期待しているか
- 実際には何が起きるか

再現できない場合は、修正より先に観測方法を検討する。


# 2. Observe

`../VERIFY.md` から適切な検証・観測方法を選ぶ。

原因が見えない場合は、
コード変更より先に観測手段を増やす。

症状と原因を混同しない。

遅さ・動作不良はアプリ起因とは限らない。環境・テストハーネス・ツール起因のことがあるため、推測でなく実測して切り分ける（例: アプリが遅いのではなく、WebDriverの特定操作が遅いだけ、だったケース）。


# 3. Isolate

問題の発生範囲を小さくする。

正常な部分と異常な部分を分け、
原因候補を観測結果から絞る。

複数の原因候補を同時に変更しない。


# 4. Fix

原因を説明できる状態になってから、
必要な範囲だけを修正する。

無関係なリファクタリングや改善を混ぜない。


# 5. Verify

不具合が再現しなくなったことを確認する。

同時に、変更した周辺の正常な動作が
壊れていないことも確認する。


# 6. Escalate

十分に観測・切り分けしても原因を特定できない場合は、
同じ試行を繰り返さない。

観測結果と試した内容をまとめ、
上位モデルへの相談や別の調査方法を検討する。


# Output

完了時には最低限、以下が分かる状態にする。

- 何が原因だったか
- 何を修正したか
- どう検証したか
- 周辺への影響を確認できたか
